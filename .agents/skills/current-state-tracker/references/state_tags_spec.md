# State Tags Taxonomy & Lifecycle Specification

본 규격서는 샌드박스 다중 턴 개발 환경에서 작업 항목의 진행 상태를 추적하고 태깅하기 위한 공식 8단계 상태 전이 규칙서입니다.

---

## 1. 8단계 상태 태그 정의 (State Tags Definition)

```text
[REQUESTED] ──▶ [PLANNED] ──▶ [IN_PROGRESS] ──▶ [STAGED] ──▶ [VERIFIED] ──▶ [READY_FOR_AUDIT]
      │                                             │               │
      └─── (의존성 대기 시) ──────────────────────────┴─▶ [BLOCKED]    │
                                                                   │
                                 [REVISION] ◀── (결함 발견 시) ────┘
```

### 1) `[REQUESTED]` (지시 접수)
* **정의**: 사용자가 프롬프트를 통해 요구한 사항이 인입되었으나, 아직 에이전트가 이를 분석하거나 구체적인 구현 계획을 수립하지 않은 초기 대기 상태입니다.
* **목적**: 사용자의 지시사항이 중간에 유실되거나 누락되는 것을 방지합니다.

### 2) `[PLANNED]` (계획 완료)
* **정의**: 요구사항에 대한 분석이 완료되어, 담당 파일 경로, 작업 순서, 턴 목표가 구체적으로 확정된 상태입니다.

### 3) `[IN_PROGRESS]` (구현 진행)
* **정의**: 현재 활성 턴에서 샌드박스 파일에 대한 실제 코드/문서 작성 또는 수정 작업이 이루어지고 있는 상태입니다.
* **규칙**: 어텐션 분산을 막기 위해 한 번에 오직 하나의 작업만 `[IN_PROGRESS]`로 유지하는 것을 권장합니다.

### 4) `[STAGED]` (초안 작성)
* **정의**: 샌드박스 내에 코드 또는 텍스트 작성이 완료되었으나, 아직 실행, 빌드 검사, 단위 테스트를 거치지 않은 상태입니다.

### 5) `[VERIFIED]` (로컬 검증)
* **정의**: 샌드박스 내부에서 문법 검사(Syntax check), 단위 테스트, 또는 스모크 체크를 통과하여 최소한의 동작 신뢰성이 확보된 상태입니다.

### 6) `[BLOCKED]` (의존성 대기)
* **정의**: 다른 선행 작업(예: 데이터베이스 연결 모듈, 기반 인터페이스 정의)이 아직 완료되지 않아 후속 작업을 진행할 수 없는 대기 상태입니다.

### 7) `[REVISION]` (보완 필요)
* **정의**: 게이트키퍼 심사 또는 자체 검증 과정에서 결함, 엣지 케이스 누락, 코드 스멜이 발견되어 재작업이 필요한 상태입니다.

### 8) `[READY_FOR_AUDIT]` (심사 대기)
* **정의**: 계획된 모든 세부 작업 항목이 `[VERIFIED]` 상태에 도달하여, 게이트키퍼에게 일괄 종합 심사를 요청할 준비가 완료된 상태입니다.
